# v0.6.0

## 破坏性变更

- 插件不再启动 opencode 服务。它接入你已经跑着的那个服务——由 `opencode service start` 提供、注册在
  `~/.local/state/opencode/service*.json` 的那个。找不到服务时插件显示「未发现服务」和要跑的命令，
  每 10 秒重试一次，服务出现后自动接上。启动/停止命令与 `autoStart` 设置一并删除，插件也不再终止
  任何 opencode 进程。
- 只支持 opencode v2 的 `/api/*` 契约。健康判据是 `GET /api/info`（200 + JSON 带 `version`/`pid`），
  会话是 `/api/session`，事件是 `/api/event`。V1 的 `/global/health`、`/session`、`/event` 与
  `x-opencode-directory` 全部移除：opencode 2.1.3 对这些路径返回 SPA 的 HTML 加 200，旧代码会把
  HTML 当 JSON 解析，把真实失败藏成解析错误。
- 设置项收敛。删除 `port`、`hostname`、`autoStart`、`opencodePath`、`useCustomCommand`、
  `customCommand`、`startupTimeout`、`keyboardBridge`，新增 `serviceName`（`auto` 或具体注册文件名）。
  旧键在加载设置时丢弃，不需要手工清理 `data.json`。
- 上下文注入改为 prompt 的 `files` 附件，命名 `obsidian-context:<kind>:<label>[:<range>]`，内容以
  `data:text/plain;base64` 携带。插件不再往会话里写 synthetic 上下文消息，因此「从历史恢复上下文卡片」
  与「删除上下文消息」这两个能力随之取消——v2 没有删除已投递消息的接口，保留它们只能是假象。
- 删除 web UI 键盘快捷键桥与终端主题补丁。它们靠改写上游 JS bundle 的字符串锚点实现，opencode 2.1.3
  的 601 个 asset 上这些锚点已经 0 命中，实际早已静默失效。

## 修复

- 切换到另一个服务后，事件流仍连在旧服务上：`start()` 见到已有请求就直接返回，只改了记录用的字段。
  现在按 endpoint 判定，目标变了就销毁旧连接重连。
- opencode 进程被杀后插件停在 attached 不重试：原来只把「流正常结束」当作服务消失，读错误
  （`read ECONNRESET`）与路由不可用被忽略。现在任一终态都降级到 unavailable 并由重试定时器接管。
- 新建会话落进服务进程的当前目录：v2 的 `POST /api/session` 只认 body 里的
  `location.directory`，query 参数与 `x-opencode-directory` 头都不生效。

## 说明

- 服务是否还活着由 `/api/event` 的连接终态表达，插件不做轮询：断了就是不可用，10 秒后重试。
- 插件不持有会话状态。会话、模型、凭据都在 opencode 那一侧，换机器或换服务不需要迁移插件数据。
- 需要 opencode v2.1.3 或更新的 v2 版本。
