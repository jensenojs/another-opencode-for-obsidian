# v0.5.0

## OpenCode v2 web UI 路由适配

修复 v2 下插件面板打开后显示「出了点问题 加载应用程序时发生错误」的问题。

- opencode v2 的 web UI 路由方案变了：会话深链从 v1 的 `/<base64(projectDir)>/session/<id>` 改为 `/server/<base64(serverURL)>/session/<id>`。v2 SPA 无法解析 v1 格式的路径。
- 插件现在从 `/api/health` 响应中读取 `version`：主版本 ≥ 2 时生成 v2 路由方案，v1 服务器行为完全不变。
- server 状态变为 running 时刷新 client 的 base URL（此前只在插件加载时设置一次，存在时序盲区）。
- `reloadIframe` 现在从当前 iframe URL 提取会话后缀并用最新 base 重建，不再原样重载旧方案 URL。

此前两个前置修复（随本版本一并验证）：

- 代理转发时剥离 `accept-encoding`，避免对 gzip 压缩响应做文本注入导致 `ERR_CONTENT_DECODING_FAILED`（面板卡在 loading）。
- web UI 代理的 HTTP 请求与 WebSocket 升级均注入 Basic Authorization（v2 强制鉴权，iframe 不自动带凭据）。

## 已知限制

- 深链恢复依赖 `/session/<id>` 后缀正则，UI 内部其他路径（如 `/new-session`）在 server 重启后会回落到根路径。

## 验证

通过 CDP（浏览器调试协议）驱动真实 Obsidian 端到端验证：iframe 实际加载 v2 路由并渲染会话正文，无报错页。321 tests pass。
